# 互动剧协议创作 Skill 使用说明

## 1. 这是什么

`interactive-drama-author` 用于把自然语言故事、小说大纲或已经审核的剧情方案，改编为 Alfred 管理平台可预检和导入的互动剧协议。

它负责：

- 规划章、集、播放单元、台词、分支、状态和结局。
- 规划角色、场景、立绘、配音和 BGM 等素材需求及生成 Prompt。
- 检查数量、引用、分支可达性、状态规则和协议结构。
- 最终只交付一份 `剧情协议.json`。

它不负责生成图片或音频，不调用收费供应商，不上传管理平台，也不发布剧目。

## 2. 包内文件

| 路径 | 用途 |
| --- | --- |
| `SKILL.md` | Agent 执行入口和强制交付规则 |
| `references/` | 协议语义、创作流程、素材规划和平台兼容边界 |
| `schemas/` | 内容协议和生成请求的 JSON Schema |
| `scripts/validate.py` | 无第三方依赖的离线校验器 |
| `examples/` | 线性剧和分支剧的完整示例 |
| `tests/` | 校验器回归测试 |
| `agents/openai.yaml` | Codex 等支持 Skill 的产品所需界面元数据 |
| `VERSION` | Skill 版本 |

`.git`、`.DS_Store`、`__pycache__` 和 `.pyc` 不属于交付包。

## 3. 如何交给 Agent

### 3.1 Codex、Claude Code、Cursor、DeepSeek Harness

把完整仓库目录复制或解压到 Agent 可读取的位置，然后发送：

> 使用 `interactive-drama-author` Skill。先完整读取 `SKILL.md`，并按其中引用的协议、Schema、示例和校验器执行。根据我提供的原稿与数量约束生成互动剧，实际运行离线校验，最终只交付一份 `剧情协议.json`。不要生成图片、音频、压缩包或其他附带文件。

支持原生 Skill 安装的产品，可将整个 `interactive-drama-author` 目录安装到其 Skill 目录。不要只复制 `SKILL.md`，否则 Agent 无法读取 Schema、示例和校验器。

### 3.2 在线 Grok 或普通聊天产品

优先上传完整 ZIP，并要求模型先解压、读取 `SKILL.md` 及其引用文件。如果产品不能读取 ZIP，应至少上传：

- `SKILL.md`
- `references/`
- `schemas/`
- 与本次内容类型相符的 `examples/`

普通聊天产品可能无法运行 Python 校验器。此时模型只能生成候选 JSON，不能声称已经通过机器校验；下载后必须在本地运行 `scripts/validate.py`。

## 4. 推荐输入

至少提供以下信息：

- 原始故事或剧情大纲。
- 必须保留的人物、关系、转折和结局。
- 允许新增、删减或改写的范围。
- 章数、每章集数、每集播放单元数。
- 每个播放单元期望的台词数量。
- 结局数量以及是否需要状态变量或条件分支。
- 素材数量或制作预算限制。

如果数量尚未确定，可以明确授权 Agent 自行规划，但 Agent 必须在生成前说明采用的数量，不能默默猜测。

示例：

> 将这份大纲改编为 8 章，每章 7 集，每集 6 个播放单元，每单元 3～5 句台词。保留主角动机和最终真相，允许增加支线；设计 3 个结局，单次主路线目标时长约 2 小时。规划素材需求和 Prompt，但不生成素材。完成后实际运行校验，只交付 `剧情协议.json`。

## 5. 唯一交付物

最终交付目录只能包含：

```text
剧情协议.json
```

原稿副本、生成请求、展开计划、校验报告、审阅说明、提示词文档、压缩包、图片和音频都不是最终交付物。需要这些中间数据时只能放在临时目录，或者在对话回复中简要说明。

协议中的 `asset_specs` 只是素材需求和 Prompt；`asset_bindings` 只有在用户明确提供可信成品标识时才可填写。Agent 不得编造成品 ID、数据库 ID、文件状态或审核结果。

## 6. 离线校验

环境要求：Python 3.10 或更高版本，无需安装第三方依赖。

校验示例：

```sh
python3 scripts/validate.py 剧情协议.json
```

需要同时核对用户要求的章、集、单元和结局数量时，可在临时目录生成请求文件：

```sh
python3 scripts/validate.py --plan --request /tmp/generation-request.json
python3 scripts/validate.py 剧情协议.json --request /tmp/generation-request.json
```

退出码：

- `0`：本次离线校验通过。
- `1`：协议内容或数量不符合要求。
- `2`：输入文件或校验器运行错误。

最多进行三轮定点修复，每轮都必须重新执行完整校验。`valid=true` 只代表离线结构检查通过，不代表剧情质量、人审、媒体可用性或发布检查通过。

## 7. 导入 Alfred

1. 在 Alfred 剧目列表选择上传剧情协议。
2. 选择 `剧情协议.json`。
3. 查看服务器预检结果和实际数量。
4. 无阻断问题后导入为新剧或新草稿版本。
5. 在管理平台继续完成剧情审核、素材制作、试玩和发布检查。

导入不会自动批准剧情、生成收费素材或发布剧目。服务器会重新校验协议，不能用本地报告绕过预检。

## 8. 素材口径

- 图片需求最长边默认不超过 1.5K（1536 像素），除非用户明确批准更高分辨率。
- 实际图片模型、压缩、费用和候选管理由 Alfred 生成流程负责，不写入当前协议。
- 配音正文必须与台词一致；音频参数只能使用当前 Schema 支持的字段。
- 相同背景、角色定妆和可复用姿态只定义一次，具体播放单元显式引用。

## 9. 修改已有剧

局部修订必须保留未修改实体的稳定 `key`。只改台词时不得顺便增删播放单元；修改共享素材 Prompt 时，应在回复中列出所有受影响的引用位置，并提醒重新审核。

修订完成后仍需全剧校验，不能把单章或单集通过等同于整部剧通过。

## 10. 版本与维护

当前 Skill 版本见 `VERSION`，当前创作协议版本写在 `剧情协议.json` 的 `protocol_version` 中。升级协议时必须同步更新：

- `SKILL.md`
- `references/`
- `schemas/`
- `examples/`
- `scripts/validate.py`
- `tests/`

业务仓库与 Skill 仓库的 Schema 必须保持一致。修改后至少运行 Skill 结构检查、校验器测试、示例校验和业务仓库协议样本校验。
