# 素材需求与复用

一个全剧目录，显式引用。owner表示主要归属，不限制其他集使用，也不产生同名覆盖：

| 归属 | 适合的内容 |
| --- | --- |
| 剧 | 主角色定妆、音色、常驻地点、风格 |
| 章 | 地域/季节/服装阶段与共用场景变体 |
| 集 | 当天时段、道具状态、局部配乐 |
| 单元 | 特定构图/动作/表情/逐句配音 |

不要求每层都新增资产。同一背景供多个单元使用时仅建一条需求，在各单元显式引用。参考目录不等于播放目录；asset_refs里有一个人物定妆不代表它自动上屏。

## 生产模式

- create：新建，必须prompt。
- derive：基于已有需求/成品派生，必须prompt和非空references。
- reuse：直接绑定已有成品，必须由用户输入提供可信binding，不能杜撰。
- upload：等待人工上传，可暂时没有prompt或binding。

引用依赖无环。先定妆/风格参考，再服装/姿态与场景变体，最后具体画面。角色reference本身未生成时依赖任务等待，不自动降级纯文生图。

每条需求包括name、description、reason、owner、usage、media_type、production_mode、references、specifications以及生成所需prompt。使用方便阅读的名称；路径、数字ID不代替人类名称。

## Prompt内容

图像prompt说明主体/动作、角色固定特征、服装、场景状态、构图、光线、风格和应避免的偏差；关键身份同时通过references引用定妆。分层pose通常透明背景；single_image是完整画面，不能误把独立角色立绘当完整场景。

配音说明准确正文、情绪和语速，以及可用音色参考；spoken_text不能脱离对白独立改写。BGM说明情绪、乐器、速度、时长与是否循环；voice_profile是声音身份元数据，不能播放。

不要认为只有prompt文字就能保证身份一致。供应商集成需要把references解析为选定成品并传入实际API；本skill不调用供应商。音视频实际时长、媒体真伪、视觉一致性需后续验收。

## 交付前反查

每个单元画面、角色层、配音、BGM和结局引用都有相容需求。所有预算内需求都有用途；非播放参考说明原因。昼夜/服装/伤势等不兼容状态拆成派生需求。程序报告asset_usage辅助查找，但不能替代判断美术复用是否合理。

在review-notes列出需求总数、create/derive/reuse/upload数量、关键共享项、依赖顺序和待审核项。没有供应商报价不要伪造费用。
